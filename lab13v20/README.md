# Лабораторна робота №13

**Тема:** Власні винятки та патерн Result.

**Варіант:** 20 — Управління бібліотекою

**Мета:** Навчитися створювати власні типи винятків для специфічних помилок, а також реалізовувати патерн Result для контрольованої обробки помилок без використання винятків у «нормальних» сценаріях невдачі.

**Хід роботи:**
1. Створив консольний проєкт lab13v20 у папці OOP-Rybonka командою `dotnet new console -o OOP-Rybonka/lab13v20`.
2. Створив власний виняток `BookNotAvailableException : Exception`:
   - три стандартні конструктори: без параметрів, `(message)`, `(message, innerException)`;
   - конструктор з контекстом і властивості `BookTitle`, `UserName`, `ExistsInCatalog` (книги немає в каталозі чи всі примірники видано).
3. Реалізував узагальнений клас `Result<T>`:
   - властивості `IsSuccess`, `Value`, `Error`;
   - приватний конструктор `Result(T value, bool isSuccess, string error)`;
   - фабричні методи `Success(T value)`, `Failure(string error)` і `Failure(Exception ex)`.
4. Реалізував клас `LibraryService` (книги зберігаються в `Dictionary` без урахування регістру, видачі — окремо для кожного читача):
   - `void BorrowBook(string bookTitle, string userName)` — викидає `BookNotAvailableException`, якщо книги немає в каталозі або всі примірники видано, і `ArgumentException` для порожніх даних;
   - `Result<bool> ReturnBook(string bookTitle, string userName)` — повертає `Failure`, якщо читач цю книгу не брав, інакше `Success(true)`;
   - `Result<Book> FindBook(string bookTitle)` — пошук книги; технічний виняток перетворюється на `Result` через `Failure(Exception)`.
5. У `Main` продемонстрував:
   - видачу книг з обробкою `BookNotAvailableException` у `try-catch`; за властивістю `ExistsInCatalog` читачу пропонується черга або міжбібліотечний абонемент;
   - повернення книг з перевіркою `IsSuccess` / `Error`;
   - повторну видачу книги після її повернення;
   - пошук книг і всі три стандартні конструктори винятку.
6. Запустив програму командою `dotnet run`.

**Висновок:** Для `BorrowBook` обрано виняток: якщо книгу неможливо видати, метод не виконує свій контракт, і викликач не повинен цього пропустити. Властивості винятку дозволяють одразу запропонувати читачу альтернативу. Для `ReturnBook` і `FindBook` обрано `Result<T>`: помилка бібліотекаря при поверненні чи пошук без результату — звичайні, очікувані ситуації, тому дешевше і зрозуміліше повернути результат, ніж кидати виняток.

**Контрольні питання:**
1. Власні винятки дозволяють перехоплювати саме помилки предметної області і передавати контекст у властивостях, а не лише в тексті.
2. Без параметрів; `(string message)`; `(string message, Exception innerException)`.
3. `Result<T>` містить або значення, або опис помилки. Він доцільний для очікуваних неуспіхів, бо дешевший за виняток і видний у сигнатурі методу.
4. Винятки — коли метод не може виконати контракт і для технічних збоїв; Result — для передбачуваних варіантів відповіді (валідація, «не знайдено», «не брав цю книгу»).
