# Самостійна робота №13 (IndependentWork7)

**Тема:** Узагальнений кеш `Cache<TKey, TValue>` із тестами.

**Мета:** Розробити узагальнений клас кешу з обмеженою ємністю та політикою видалення найстаріших елементів (FIFO) і перевірити його юніт-тестами.

**Хід роботи:**
1. Створив рішення `IndependentWork7.sln` з консольним проєктом `IndependentWork7` і тестовим проєктом `IndependentWork7.Tests` (xUnit), який посилається на основний проєкт.
2. Реалізував клас `Cache<TKey, TValue>` (`Cache.cs`):
   - приватні поля `_capacity`, `_cache` (`Dictionary<TKey, TValue>`) і `_keysOrder` (`Queue<TKey>`) для порядку додавання;
   - конструктор `Cache(int capacity)` з перевіркою, що ємність більша за 0;
   - `Add` — якщо кеш повний, через `Dequeue()` видаляє найстаріший ключ і прибирає його зі словника; повторне додавання наявного ключа лише оновлює значення;
   - `Get` — використовує `TryGetValue` і викидає `KeyNotFoundException` для відсутнього ключа;
   - `ContainsKey` і властивість `Count`.
3. Написав 14 юніт-тестів (`CacheTests.cs`): додавання, отримання, витіснення найстарішого при переповненні (зокрема кілька переповнень поспіль і ємність 1), `KeyNotFoundException`, `ContainsKey`, `Count`, некоректна ємність.
4. У `Main` продемонстрував роботу `Cache<string, string>` (словник перекладів) і `Cache<int, Student>`.

**Висновок:** Поєднання `Dictionary` (пошук за O(1)) і `Queue` (порядок додавання) дає простий і швидкий FIFO-кеш, а окремий тест на кожен метод і на граничні випадки переповнення дозволяє швидко знайти помилку в політиці витіснення.

**Запуск:**
```
cd IndependentWork7
dotnet run --project IndependentWork7
dotnet test
```
