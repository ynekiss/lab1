# Самостійна робота №10. Інвертований індекс і вимірювання продуктивності (InvertedIndexDemo)

**Мета:** Розробити власну реалізацію інвертованого індексу для повнотекстового пошуку та порівняти його продуктивність з лінійним пошуком.

**Хід роботи:**
1. Створив консольний проєкт `InvertedIndexDemo`.
2. Реалізував класи:
   - `Document.cs` — документ (`Id`, `Title`, `Content`);
   - `TextProcessor.cs` — `Tokenize` (Regex `[\w#+]+` + нижній регістр, тому `C#` і `C++` лишаються цілими словами), `RemoveStopWords`, `Normalize`;
   - `InvertedIndex.cs` — `AddDocument`, `SearchSingleWord`, `SearchMultipleWords` (AND через `IntersectWith`), `SearchAnyWord` (OR через `UnionWith`); із завдань з зірочкою — `SearchPhrase`, `SearchRanked` (TF-IDF) і `Highlight`;
   - `PerformanceTest.cs` — генерація 10/100/1000/10000 документів і порівняння лінійного пошуку з пошуком в індексі.
3. У `Program.cs` зробив демонстрацію пошуку, бенчмарк і інтерактивний режим пошуку з підсвічуванням знайдених слів.
4. Виміряв час пошуку й побудови індексу, порахував, після скількох запитів індекс окуповується, і записав висновки.

**Звіт з таблицею вимірювань і висновками: [REPORT.md](REPORT.md)**

**Висновок:** Інвертований індекс окуповується вже після 2–5 пошуків. Далі кожен запит виконується в десятки чи сотні разів швидше за лінійний пошук, і перевага зростає з кількістю документів.

**Запуск:**
```
cd InvertedIndexDemo
dotnet run -c Release
dotnet run -c Release -- --no-interactive   # без інтерактивного режиму
```
